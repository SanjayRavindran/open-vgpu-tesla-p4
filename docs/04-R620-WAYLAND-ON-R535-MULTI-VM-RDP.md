## 2. Issues Ironed Out After UEFI Coreboot & 50/50 `GRID P4-4Q` Upgrade

1. **Missing `br0` Bridge & DHCP Client-ID Drift on `.24`:**
   - `/etc/netplan/00-installer-config.yaml` previously only configured `eno0`. Moving `eno0` into `br0` under `systemd-networkd` changed the DHCPv4 IAID and caused the router to assign `.26`/`.27`.
   - **Fix:** Configured `br0` statically at `192.168.1.24/24` with gateway `192.168.1.1` and MAC `d0:50:99:7c:84:dd` in `/etc/netplan/00-installer-config.yaml`, and enabled `/etc/systemd/system/vgpu-vms.service` so both VMs start automatically on host boot.
2. **Host `dmesg` `NVRM: API mismatch (580.178.04 vs 535.309.01)`:**
   - Residual `580.178.04` libraries in `/usr/lib/x86_64-linux-gnu/` were being loaded by `nvidia-cdi-refresh.service` against the `535.309.01-vgpu-kvm` kernel module.
   - **Fix:** Removed leftover `580.178.04` host `.so` files and symlinked `/usr/bin/nvidia-smi` and `/usr/lib/x86_64-linux-gnu/libnvidia-ml.so.1` to `/opt/nvidia-vgpu-535/`.
3. **Windows 11 `GRID P4-4Q` (`SUBSYS_120610DE`), GPU-Z & NVIDIA Control Panel:**
   - Switching `vm-win11` from `GRID P4-1Q` (`SUBSYS_120410DE`) to `GRID P4-4Q` (`SUBSYS_120610DE`) exposed a new PCI Subsystem ID that remained an unbound `Video Controller (VGA Compatible)` while `Microsoft Basic Display Adapter` (`PCI\VEN_1234&DEV_1111`) took over as primary display.
   - **Fix:** Bound `nvgridsw.inf` from DriverStore to `PCI\VEN_10DE&DEV_1BB3&SUBSYS_120610DE` (`pnputil /add-driver ... /install`), removed the phantom `1Q` device, disabled `Microsoft Basic Display Adapter` (`Disable-PnpDevice`), and added a Desktop shortcut for the AppX **NVIDIA Control Panel (`NVIDIACorp.NVIDIAControlPanel_8.1.969.0`)**. Both **TechPowerUp GPU-Z 2.71.0** (`4096 MB GDDR5`, DirectX 12 `12_1`, OpenGL `4.6`, Vulkan, CUDA, OpenCL, DirectCompute, DirectML) and **NVIDIA Control Panel (`539.72 — GRID P4-4Q`)** open cleanly over RDP.
4. **AlmaLinux 10.3 (`x86_64_v2`) Docker + NVIDIA Container Toolkit + Selkies/PixelFlux `10-bit` & `4:4:4`:**
   - Upstream `el10` Docker/NCT binaries carry an `.note.gnu.property` `x86-64-v3` ELF marker that glibc rejects on Ivy Bridge (`x86-64-v2`), and `535.309.01` leaves old `libnvidia-egl-gbm.so.1.1.0` / `libnvidia-egl-wayland.so.1.1.11` files alongside R620's `1.1.3` / `1.1.20`.
   - **Fix ([`scripts/setup_selkies_pixelflux_vgpu.sh`](../scripts/setup_selkies_pixelflux_vgpu.sh)):** Removes superseded `1.1.0`/`1.1.11` EGL files, strips `.note.gnu.property` from container binaries, installs an `x86-64-v2`-clean `/usr/bin/runc`, generates `/etc/cdi/nvidia.yaml` & `/var/run/cdi/nvidia.yaml`, and launches [`docker-compose.yml`](../docker-compose.yml) with `SELKIES_ENCODER=h265enc,h264enc`, `SELKIES_VIDEO_FULLCOLOR=true`, `SELKIES_VIDEO_10BIT=true`, and `GBM_BACKENDS_PATH=/usr/lib64/gbm:/usr/lib/x86_64-linux-gnu/gbm`.
5. **FastAPI-DLS (`https://192.168.1.24:443`) Delegated License Service Deployment & 90-Day Guest Leases:**
   - Deployed [`fastapi-dls`](https://git.collinwebdesigns.de/oscar.krause/fastapi-dls) (`collinwebdesigns/fastapi-dls:latest`, `VERSION: 2.0.3`) on the host at `https://192.168.1.24:443` (`/opt/fastapi-dls` and `/opt/docker/fastapi-dls/docker-compose.yml`) with a 10-year X.509 keypair (`webserver.crt` / `webserver.key`) and 90-day lease duration.
   - Activated **Windows 11 (`192.168.1.65`)** via `https://192.168.1.24/-/client-token` -> `C:\Program Files\NVIDIA Corporation\vGPU Licensing\ClientConfigToken\client_configuration_token_*.tok` + `Restart-Service NVDisplay.ContainerLocalSystem` (`Product Name: NVIDIA RTX Virtual Workstation`, `License Status: Licensed`).
   - Activated **AlmaLinux 10.3 (`192.168.1.68`)** via `https://192.168.1.24/-/client-token` -> `/etc/nvidia/ClientConfigToken/client_configuration_token_*.tok` + `systemctl restart nvidia-gridd` (`Product Name: NVIDIA RTX Virtual Workstation`, `License Status: Licensed`).
6. **AlmaLinux 10.3 Direct Headless Wayland RDP vs. macOS RDP NLA Handover Failure (`0x8009030f`):**
   - System-wide `gnome-remote-desktop.service` (`--system` Remote Login mode) redirects incoming connections to `org.gnome.RemoteDesktop.Handover.desktop` using a temporary one-time SAM database token. On macOS Windows App clients (`[OS X platform]`), NLA Message Integrity Check fails on the redirected connection (`ntlm_read_AuthenticateMessage: SEC_E_MESSAGE_ALTERED 0x8009030f`) and pops up `"The Credentials Did Not Work (Username: zero)"`, which the Handover daemon rejects with `Could not find user in SAM database`.
   - **Fix:** Disabled `--system` `gnome-remote-desktop.service`, configured GDM auto-login for `zero` (`/etc/gdm/custom.conf`), created `/etc/systemd/user/org.gnome.Shell@wayland.service.d/override.conf` launching `/usr/bin/gnome-shell --no-x11 --headless`, and enabled `gnome-remote-desktop-headless.service` listening directly on `:3389` with `GKeyFile` credentials (`zero` / `sanjay`, zero Server Redirection).
7. **AlmaLinux 10.3 GTK4 Vulkan-on-Wayland Swapchain Segfault (`libnvidia-vulkan-producer.so`) Fix:**
   - GTK4 (`gtk4-4.16.7` in AlmaLinux 10.3) defaults to the `vulkan` GDK renderer (`gdk_vulkan_context_check_swapchain`), which invokes R535's `libnvidia-vulkan-producer.so` (`ProducerCleanup`) and segfaults (`SIGSEGV`) when creating a Wayland swapchain against R620's `libnvidia-egl-wayland.so.1.1.20`.
   - **Fix:** Persisted `GSK_RENDERER=ngl` (GTK4's hardware-accelerated OpenGL 4.6 / EGL renderer on `GRID P4-4Q`) across `/etc/environment`, `/etc/profile.d/gsk-renderer.sh`, `/etc/systemd/user.conf.d/gsk-renderer.conf`, `/etc/systemd/user/org.gnome.Shell@wayland.service.d/override.conf`, and the `systemd --user` / D-Bus activation environment (`WAYLAND_DISPLAY=wayland-0`, `XDG_SESSION_TYPE=wayland`, `XDG_CURRENT_DESKTOP=GNOME`). All GTK4 apps (`ptyxis`, `nautilus`, `gnome-control-center`) launch and render on `GRID P4-4Q`.
8. **Windows 11 RDP `Error code: 0x200d` (`DecompressionFailed` / `0x8007007A`) & NLA Session Arbitration:**
   - When a Retina macOS RDP client requests dynamic resolution `3600 × 2262` (`RdpCoreTS` Event `168`) while `AVCHardwareEncodePreferred=1` forces the `NVIDIA H.264 Encoder MFT` on the RDP transport stream, `RDP_GFX` fails with `0x8007007A` (`ERROR_INSUFFICIENT_BUFFER`), dropping the session with `Error code: 0x200d`.
   - Additionally, force-restarting `TermService` live on Windows (`Restart-Service TermService -Force`) invalidates `LocalSessionManager`'s service handle (`reason code 12`), and setting `UserAuthentication=0` spawns a pre-logon session that sits on `"Other user — Welcome"` for ~12 seconds during session arbitration.
   - **Fix:** Removed the `AVCHardwareEncodePreferred` policy override (keeping `NVIDIA GRID P4-4Q` active for all DWM, DirectX 12, Vulkan, OpenGL 4.6, CUDA, NVENC/NVDEC, GPU-Z, and NVIDIA Control Panel workloads), configured `.rdp` profiles for `1920 × 1080` (`dynamic resolution:i:0`, `smart sizing:i:1`), and enabled NLA (`UserAuthentication=1`) for instant session attachment.
